It addresses the conditional conflict in the [strict-calendar analysis](PULSE-STRICT-CALENDAR-OBSTRUCTION.md) by explicitly allowing one graph edge with zero duration and by supplying the boundary order as an original-operation program. It does not claim that the existing strict `Calendar` or its compiler accept that edge.

## Graph and ages

Let `R` be the root, `AB` the A/B join, `D` the donor vertex, `H` the hybrid vertex, and `A,B,C` the sampled tips. Edges point from older to younger. All three tips have age zero; `age(H) = age(D) = h`, `age(AB) = t1` and `age(R) = t0`.

| Edge ID | Original edge | Intended rate | Duration |
| --- | --- | --- | --- |
| 0 | `R → AB` | `rAB` | `t0 − t1` |
| 1 | `R → D` | `rC` | `t0 − h` |
| 2 | `AB → A` | `rA` | `t1` |
| 3 | `AB → H` | `rB` | `t1 − h` |
| 4 | `D → C` | `rC` | `h` |
| 5 | `D → H` | `1` | `0` |
| 6 | `H → B` | `rB` | `h` |

The age inequalities `0 < h < t1 < t0` make every duration positive except edge 5. Choosing `1` as that edge's positive source rate is a concrete placeholder, not a new equality among model parameters. Its irrelevance requires proof that the timed program gives edge 5 no positive-time exposure **and** that the provider's rate-dependent uniformization bookkeeping cancels on the relevant supported states. The uniformization note (internal supporting file not included: `UNUSED-EDGE-UNIFORMIZATION.md`) records the actual dependency and a proposed restricted-generator argument.

The graph has root indegree/outdegree `(0,2)`, sampled tips `(1,0)`, `AB` and `D` `(1,2)`, and `H` `(2,1)`. Each vertex is reachable from `R`, and every edge points to a greater vertex index in the candidate, giving a directed acyclic graph. The two routes `R → AB → A` and `R → D → C` meet only at `R`, so no other vertex dominates all three tips. A local in-memory structural check of the source's seven edge maps independently checked these finite degree, reachability and root-dominator properties; it did not run Lean, a stochastic model or any probability calculation. The source's corresponding proof terms remain unchecked.

The two parent edges of `H` are 3 and 5. Parent bit `false` selects 3, the continuation of B; `true` selects 5, the donor connection. The existing [pulse measure](https://raw.githubusercontent.com/Sodelin/Research-Commons/14be42189b8a72fcaced51ceda4e86445dc09e90/packages/research/vendor/accepted/predecessor-check493/source-store/04a3a1c1f027903e62b77f966639c80da77aaa776871a0d9bd0657eac35b9e4f.lean) uses the Bernoulli law on `true` with parameter `g`, as specified by the pinned [Mathlib Bernoulli definition](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/Probability/Distributions/Bernoulli.lean). The actual owner/block and current-state mapping is still a proof obligation.

A separate rational forest helper assigns its numerical parameter to `false`, rather than `true`. The selected boundary definition above uses the measure path; any later use of the rational helper must explicitly reconcile parameter, bit and type conventions. The [source comparison](PULSE-COIN-CONVENTION-COMPARISON.md) records the exact interfaces and the limits of this reading.

## Explicit boundary order at `h`

At the end of the first interval, the candidate program applies the following operations **without an interval between them**:

1. Exit edge 6, placing current B roots at `H`; exit edge 4, placing current C roots at `D`.
2. Apply the existing independent pulse at `H`: a current B root stays on edge 3 for `false`, or enters the zero-duration edge 5 for `true`.
3. Exit edge 5, placing migrated B roots at `D` alongside the existing C roots.
4. Enter edge 1 at `D`, putting both kinds of C-population roots on the same original physical edge.

The hybrid pulse indexes one coin by each current root at `H`, so the intended mapping gives a previously merged B block one coin. The original C roots are at `D`, not `H`, and thus do not receive a pulse coin. No within-edge clock is run between the routing and zero-edge exit. These statements describe the intended effect of the operation definitions; equality of the actual code/PMF support with the manuscript's pulse remains to be proved.

The upper C edge 1 targets `D`, and `D` reaches both the C tip along edge 4 and the B tip along edges 5 and 6. Thus the earlier non-descendant objection to moving a B sample onto a **C-tip** edge does not immediately apply to edge 1. More is needed: the candidate must show the provider's `SourceValid` is preserved by each actual coded operation and that all currently carried descendants satisfy its hypothesis. The cited original operations state preservation; the new program's instantiated proofs have not been checked.

## Why the existing calendar compiler cannot be used unchanged

The proposed ages violate `Calendar.edge_older` on edge 5. The strict calendar therefore cannot simply be instantiated with this age map. Moreover, even a hypothetical removal of that inequality would not make the existing [calendar compiler](https://raw.githubusercontent.com/Sodelin/Research-Commons/14be42189b8a72fcaced51ceda4e86445dc09e90/packages/research/vendor/accepted/predecessor-check493/source-store/9974446d99fa344593d294e315e349ab71fdbe7574e932bb8b1a16ee1b2369fd.lean) schedule this event correctly: it places **all** same-date exits before **all** same-date node operations. Its exit of edge 5 would happen while the edge is still empty, before the hybrid pulse places a migrant there. The program needs the edge-5 exit *after* that pulse and before entry at `D`.

The existing [finite-program interface](https://raw.githubusercontent.com/Sodelin/Research-Commons/14be42189b8a72fcaced51ceda4e86445dc09e90/packages/research/vendor/accepted/predecessor-check493/source-store/d009fdfc510bfcaffaeea3bc241401eaf2996178ff4b82376eb22f1e49387831.lean) accepts explicitly ordered interval and boundary operations without a `Calendar` argument. This makes the hand-selected operation list a concrete candidate for reuse. It does **not** prove that this list is a physically valid weak-calendar schedule, that its interval law has the needed event-time interpretation, or that the source's strict-calendar pair-clock theorems apply to it. A general weak-calendar compiler would need a reverse-topological same-age order and new preservation/timing proofs; one is not claimed here.

A later [strict-calendar approximation plan](PULSE-STRICT-APPROXIMATION-PLAN.md) proposes moving `D` slightly older and compares endpoint codes only under explicit pulse, no-merger and scheduler premises. It also explains why the resulting raw edge-labelled path laws cannot be assumed close in total variation. Dot's r34 review conditionally accepted the stated endpoint bound and raw-path obstruction; the source scheduler, full-Code boundary and pulse commutation, coin transport and kernel split remain unproved. This scoped AI hand review is not a Lean check, a replacement for the exact zero-edge program or a checked physical/observation join.
