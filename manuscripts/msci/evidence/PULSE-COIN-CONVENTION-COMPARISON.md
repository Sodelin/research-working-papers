# Pulse coin parameters: a source-interface distinction

1 November 2026 UTC. This is a bounded reading of the source definitions, not a Lean or model check. Two source interfaces describe finite independent Boolean choices with opposite meanings for their numerical parameters. They can coexist; a proof that joins them must explicitly account for the difference.

The probability interpretation of the rational weights requires `0 ≤ p ≤ 1`. The measure row follows from `bitMeasure gamma := bernoulliMeasure true false gamma` and the pinned [Mathlib Bernoulli definition](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/Probability/Distributions/Bernoulli.lean), which assigns its parameter to its first argument. An in-memory exact-rational control checked both Boolean outcomes at `g = 1/4, 1/2, 3/4`: the one-bit weights agree when the rational `p = 1 - g`. For example, setting both numerical parameters to `1/4` instead gives true weight `3/4` in the rational interface and true mass `1/4` in the measure interface. Equal numerical parameters agree at `1/2`.

The complementary-parameter observation assumes the **same Boolean and parent interpretation**, appropriate probability bounds and compatible representations. In particular, `p : ℚ` cannot represent every real `gamma`; this note does not construct a type coercion, real extension, product-measure theorem or a proof about different coin index sets. A bit flip would also require tracking which parent each bit selects. No mismatch follows merely from the two definitions having different parameter conventions.
