# Zero preconditioning in the finite rational interval candidate

31 October 2026. This is a hand audit of the definitions in the uncompiled finite interval arithmetic (internal supporting file not included: `FiniteRationalIntervalDraft.lean`) and matrix contractor candidate (internal supporting file not included: `FiniteIntervalMatrixDraft.lean`). It does not check the Lean declarations, provide outward-rounded floating-point arithmetic, establish the MSci derivative enclosures, or prove the full interval theorem.

The manuscript uses `C ∩ K(C,O)` and says `Y=0` is a sound no-op. In the finite candidate, an interval is a pair of rational endpoints; reversed endpoints represent the empty set. Multiplication forms the minimum and maximum of the four endpoint products, which can turn a reversed input into a nonempty overapproximation. Thus the intermediate expression `K` need not be identical to `C` for an empty input, even though the final intersection can still be a no-op.

## Hand derivation for the selected finite definitions

Fix a dimension `n`, any rational point vector `q`, any finite interval vectors `Fq`, `O` and `C`, and any finite interval matrix `J`. Set the rational preconditioner `Y` to the zero matrix. No nonemptiness of `Fq`, `O` or `J` is needed for this arithmetic statement.

1. The candidate's four-corner product of `[0,0]` with any finite interval is `[0,0]`, including for reversed endpoints. Consequently the interval expressions `Y(Fq-O)` and `YJ` are zero in every coordinate.
2. Multiplication by the point interval `[1,1]` returns the endpoint hull `[min(l,u), max(l,u)]` of `[l,u]`; multiplication by `[0,0]` returns zero. In each row of `(I-YJ)(C-q)`, exactly one diagonal term contributes. The candidate sums these intervals using exact rational addition.
3. Adding the point `q` back gives the endpoint hull of each original coordinate of `C`. Therefore the finite candidate's intermediate `intervalK` at `Y=0` is the coordinatewise endpoint hull of `C`. When each interval in `C` has ordered endpoints—particularly when the required `q ∈ C` premise holds—this gives `K=C` exactly.
4. For any endpoints `l,u`, intersecting `[l,u]` with `[min(l,u),max(l,u)]` returns the original endpoint pair `[l,u]`. Thus the coordinatewise final intersection `C ∩ K` returns the original finite interval box even when an input interval has reversed endpoints. For `n=0` the coordinatewise equalities are vacuous.

For a concrete boundary example take `n=1`, `q=0`, `C=[2,1]` and `Fq=O=J=[0,0]`. The candidate's arithmetic gives `K=[1,2]`, while the final intersection is the original empty interval `[2,1]`. The manuscript's `q ∈ C` premise is false in this example; it is not a counterexample to the stated contractor theorem.

A future owner-selected Lean check can use these two exact acceptance targets: `intervalK` equals the coordinatewise endpoint hull for zero `Y`, and the coordinatewise `FiniteRationalInterval.inter` of `C` with that `intervalK` equals `C`. The theorem should be derived from the existing arithmetic definitions, not supplied as a new axiom or as the target theorem's premise. The later Lean candidate (internal supporting file not included: `FiniteZeroPreconditionerDraft.lean`) attempts these two equalities directly from the finite definitions, with no nonempty-box hypothesis. A successor derives equality of interval records explicitly from their two endpoint equalities, avoiding an assumed generated `FiniteRationalInterval.ext` lemma. The candidate and its imports remain unparsed, uncompiled and unaudited; a different interval implementation may require its own no-op proof.

## Exact-set boundary

The later soundness interface (internal supporting file not included: `SoundIntervalScalarDraft.lean`) also includes exact real-set arithmetic. It can represent unbounded sets, but its exact product sends `{0} × ∅` to `∅`, unlike the finite endpoint formula above. In a one-dimensional semantic example, take `F(x)=0`, `q=1`, `C=[1,2]`, `Fq={0}`, `J={0}`, `O=∅` and `Y=0`. Then `Fq-O=∅`, so the exact-set expression gives `K=∅` and `C ∩ K=∅`, not `C`. There are no compatible sources because `O` is empty, so the all-compatible-source inclusion remains sound. If the term “box” is defined to exclude empty intervals, this example is outside that convention; it does not refute the manuscript's inclusion.

Returning `C` directly is always a sound no-op fallback. The generic scalar soundness fields alone do not establish that the **evaluated** `Y=0` expression equals this fallback for all empty-input conventions; a particular backend needs its own proof or an explicit fallback branch. The semantic set instance is not an executable unbounded-interval backend. Its small `set_zero_mul_empty` lemma, like the rest of the new source, has not been Lean-checked.

## Nonempty input suffices for any sound backend

Suppose the represented `Fq` and `O` contain vectors `f0` and `y`, and `J` contains a real matrix `A`. For any `x` represented by `C`, scalar soundness places `f0-y` inside `Fq-O`, zero inside each relevant zero-matrix product, and `x-q` inside `C-q`. Applying the same sound operations to the remaining sums gives `x = q - 0(f0-y) + (I-0A)(x-q)` inside the evaluated `K`. Thus `C ∩ K = C` as represented sets, independently of whether the backend widens its intermediate results. This does not require `f0=y`, a compatible source, a derivative assumption, or invertibility. The witnesses are sufficient conditions, not claims that every representation is nonempty.

The backend-independent Lean candidate (internal supporting file not included: `SoundZeroPreconditionerDraft.lean`) attempts that inclusion and intersection equality with the witnesses explicit. In the manuscript setting, the stated `q ∈ C`, certified `Fq` and whole-box derivative enclosure provide the required `Fq` and `J` witnesses if their stated assumptions hold; a nonempty target box supplies the `O` witness. This candidate and its dependencies have not been parsed, compiled or axiom-audited. The separate finite-endpoint candidate above attempts a stronger result covering its reversed-input convention.

Here “no-op” means equality of **represented sets**, after exact set intersection. The generic `ScalarEnclosure` interface does not define an intersection operation, require a canonical encoding, or prove equality of the backend's returned objects. For example, a semantic backend that represents sets faithfully but returns all of `ℝ` for each point and arithmetic operation satisfies the stated enclosure-soundness fields. In a one-dimensional generic calculation with `C=[0,1]` and nonempty singleton inputs `Fq`, `O` and `J`, its evaluated `K` is `ℝ`: the exact set intersection is still `C`. A merely sound *overapproximation* of intersection, such as union, could instead return `ℝ`. This is a mathematical counterexample to inferring an implemented no-op from scalar soundness alone, not a claim that an actual backend uses that operation. A concrete contractor can ensure its fallback by returning `C` directly or by separately establishing suitable intersection behavior. The finite-rational candidate's stronger record-equality claim remains a separate, unchecked statement.
